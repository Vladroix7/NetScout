================================================================================
              NETSCOUT — WHY THE CODE WAS WRITTEN THIS WAY
================================================================================


1. WHY ASYNC/AWAIT EVERYWHERE IN THE CLIENT?
--------------------------------------------
All network operations (login, register, scanning) use async/await.

Example:
  await client.ConnectAsync(...)
  await ping.SendPingAsync(...)
  var results = await Task.WhenAll(tasks)

WHY:
  If scanning is done synchronously (blocking), the UI freezes.
  The user would see a white/frozen window and think the app crashed.
  Async lets the UI stay responsive while work happens in the background.
  WhenAll runs ALL pings at the same time — scanning 254 IPs takes seconds,
  not minutes (one by one would be 254 × 1 second = over 4 minutes).


2. WHY SemaphoreSlim IN PortDetailForm?
----------------------------------------
  private static SemaphoreSlim _semaphore = new SemaphoreSlim(100);

WHY:
  Port scan checks 1024 ports. Without limiting, 1024 TCP connections
  open at once → system runs out of sockets → crashes or gets blocked by firewall.
  SemaphoreSlim(100) = max 100 connections at the same time.
  Others wait in queue. Fast enough, safe enough.


3. WHY IS TTL USED FOR OS DETECTION?
--------------------------------------
TTL (Time To Live) is a number in the IP packet header.
Each router hop decreases it by 1.

Default starting TTL values by OS:
  Windows:    128
  Linux:      64
  macOS:      64
  Cisco:      255

If a ping comes back with TTL=125, it probably started at 128 → Windows.
If TTL=60, started at 64 → Linux or macOS.

WHY not use a real fingerprinting library?
  This is Phase 1 — a quick estimate is enough.
  Real OS fingerprinting (like Nmap) sends many special packets and
  analyzes dozens of TCP/IP stack behaviors. Much more complex.


4. WHY ARE DESIGNER.CS FILES SEPARATE?
----------------------------------------
In WinForms, Visual Studio / Rider auto-generates a .Designer.cs file
for every form. It contains all the UI initialization code
(button positions, sizes, colors, fonts, event hooks).

You should NEVER manually edit .Designer.cs.
Your logic goes in the main .cs file.

This separation:
  - Keeps generated code away from your hand-written code
  - Allows the form designer to regenerate without breaking your logic
  - Makes the main .cs file cleaner and easier to read


5. WHY NOT USE AN ORM (Entity Framework)?
-------------------------------------------
Entity Framework (EF) is a popular ORM that maps C# classes to DB tables.

It was NOT used here because:
  - Small project, simple queries — EF adds complexity for no benefit
  - Harder to debug generated SQL
  - Requires migrations for schema changes
  - Raw MySqlCommand gives full control over the query
  - Easier for someone learning to understand what SQL is being run


6. WHY static UserSession AND static Config?
----------------------------------------------
UserSession:   stores UserId, Username, IsAdmin, Email after login
Config:        stores ServerIP, ServerPort

Both are static because:
  - They hold ONE value for the whole app lifetime
  - Every form can access them without passing objects around
  - No need to create instances — they're global app state


7. WHY IS THE SERVER A SEPARATE EXE AND NOT A WINDOWS SERVICE?
----------------------------------------------------------------
A Windows Service would run in the background without a UI.
That was rejected because:
  - Admin needs a visual dashboard to see users, logs, and requests
  - Harder to develop and debug (services have no UI interaction)
  - For a local network tool, a normal WinForms app is fine
  - Admin just keeps the Server window open


8. WHY ON DELETE CASCADE IN THE DATABASE?
------------------------------------------
Example:
  Users → ScanResults → Devices → OpenPorts
                                → SecurityIssues

If a user is deleted, CASCADE automatically deletes:
  - All their scan results
  - All devices found in those scans
  - All ports found on those devices
  - All security issues on those devices

WHY:
  Without CASCADE, you'd have to manually delete in the right order.
  With CASCADE, one DELETE Users WHERE Id=X cleans up everything.
  No orphaned data left in the DB.


9. WHY PARAMETERIZED QUERIES (@e, @p) AND NOT STRING CONCATENATION?
---------------------------------------------------------------------
WRONG WAY (SQL injection risk):
  "SELECT * FROM Users WHERE Email='" + email + "'"

CORRECT WAY (what we do):
  cmd.Parameters.AddWithValue("@e", email);

If email was:  ' OR '1'='1
  Wrong way:   SELECT * FROM Users WHERE Email='' OR '1'='1'  ← logs in as anyone!
  Correct way: Treats the whole thing as a literal string → no match → safe

ALL queries in DatabaseHelper use parameterized inputs. Zero SQL injection risk.


10. WHY LOG PANEL IN ADMIN DASHBOARD?
---------------------------------------
The RichTextBox log at the bottom shows all server events in real time:
  [10:23:45] LOGIN attempt: user@test.com → SUCCESS
  [10:23:46] REGISTER: newuser@test.com → SUCCESS

WHY:
  Admin can monitor activity without looking at the DB.
  Helps debug connection issues.
  Password hashes are HIDDEN in the log (replaced with "***")
  so even if someone looks over the admin's shoulder, they see nothing useful.
